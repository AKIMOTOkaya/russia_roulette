# 本地 Web MVP 开发与运行

## 当前成果

本地版已形成可运行的多人纵向切片：房间大厅、多标签页真人、可选房间密码、房主与 Bot 管理、创建地图、多人行动、受控 Bot 回合单步推进、分类记录和胜负结算。它用于验证产品行为与抽象，不代表公网协议或安全设计已经冻结。

## 启动

需要 Rust 1.97 或兼容的 stable 工具链。在仓库根目录执行：

```bash
cargo run -p roulette-backend
```

终端会输出 <http://127.0.0.1:8787> 和本次进程的创始人临时密码。也可显式设置密码：

```bash
cargo run -p roulette-backend -- --founder-password local-only
```

等价环境变量为 `ROULETTE_FOUNDER_PASSWORD`。监听地址和端口可用 `ROULETTE_HTTP_HOST`、`ROULETTE_HTTP_PORT` 修改；`ROULETTE_LAN_EXPOSED=1` 可使局域网访问初始为开启。

服务默认监听 `0.0.0.0:8787`，但在局域网开关关闭时拒绝非本机请求。用启动时的临时密码在大厅“本机创始人”面板验证后，可实时切换该开关。该机制仅供受信任本地网络试用。

## 多人试用流程

1. 首次进入显示品牌封面。通过纵向主菜单浏览大厅、打开创建/加入对话框，或使用单人模拟快速开局。
2. 房间大厅把房间目录作为主要内容；创建、加入和游戏设置都从按钮打开模态对话框，不常驻占用大厅空间。
3. 在第一个标签页创建房间；新开其他标签页后，每页应显示不同的 `TAB · XXXX` 标识。
4. 用五位房间号加入；房间号可输入小写。设有密码时必须输入完全一致的密码。
5. 房主可继续添加 Bot；成员总数达到 3 后可输入可选种子并开局。
6. 每个真人只在自己的回合启用操作按钮。方向键移动，`Shift + 方向键` 射击，空格等待。轮到机器人时，由房主在界面点击“下一步”（或按空格/回车）推进单步行动。
7. 房主可把房主转让给其他真人或解散房间。离开进行中的房间会把自己的席位交给 Bot。

“单人模拟”仍然创建正式内存房间，再经同一 API 添加 2～5 个 Bot 并开局，因此它和多人房间共享相同的 Host 与 Core 行为。

页面每 2 秒同步视图，因此不同标签页的成员、房主和对局状态会在短时间内一致。房间数据仅在内存中，停止进程即清空。

## 开发验证

```bash
node --check clients/web/app.js
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace
```

改变 Domain 或 HTTP JSON 结构时，还应启动服务完成以下冒烟测试：

- 错误/正确密码与小写房间号；
- 两个不同 Tab ID 的真人进入同一房间；
- Bot 增删、房主转让与 3 人开局；
- 两名真人轮流提交 command，检查 revision；
- 创始人认证前后局域网开关的权限；
- 记录按 sequence 单列、自上而下呈现。

前端无包管理器或构建步骤。修改 `clients/web` 后需重新编译/运行后端，因为静态资源通过 `include_str!` 嵌入二进制。

## 下一阶段候选

1. 提供结束后原房间重开、准备状态和房间级系统记录。
2. 为浏览器轮询增加更明确的断线/超时提示，再评估 WebSocket 广播。
3. 增加可重放命令记录与本地导入/导出。
4. 改善 Bot 策略，使其观察射线、危险地形和生存收益。
5. 为全部地形和退出托管路径补齐集成测试，并做首轮规则平衡测试。
6. 本地行为稳定后，再设计公网身份、幂等、持久化和安全边界。
