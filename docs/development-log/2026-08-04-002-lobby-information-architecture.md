# 2026-08-04：封面与房间大厅信息架构调整

## 用户目标

- 降低主页标语、管理员设置和创建表单的视觉权重，让房间列表成为大厅主要内容。
- 把低频或不适合常驻的功能改成模态对话框。
- 增加品牌前置页面，以大 Logo/主视觉和纵向按钮组织单人模拟、创建、加入和设置入口。
- 如无必要不为这次布局调整引入额外前端框架。

## 范围

- 重组 `clients/web` 的页面结构、样式和前端导航状态。
- 保留现有多房间 API、Tab ID、房主/Bot 管理和对局界面。
- 增加可实际开局的单人模拟入口。
- 更新 Web 架构、开发流程、模块说明和客户端说明。

## 关键决定

1. 继续使用零构建原生前端。这次变化主要是信息层级与交互容器，现有代码无需为了布局重写为框架。
2. 首次进入显示独立品牌封面：左侧下方为纵向菜单，右侧使用 CSS 构成轮盘主视觉，不引入额外图片或 SVG 资源。
3. 房间大厅成为第二层页面，只保留紧凑标题、三个操作入口和占据主要区域的房间卡片列表。
4. 单人模拟、创建房间、加入房间和游戏/服务设置使用原生 `dialog` 模态框；设置不再常驻首页。
5. 单人模拟复用正式 `create room → add bots → start` API 链路，避免在客户端或后端增加另一套规则。
6. 离开房间后返回房间大厅；未进入房间时可在封面和大厅之间切换。

## 修改内容

- `clients/web/index.html`：新增品牌封面、纵向主菜单、独立大厅和四类模态对话框，移除大厅常驻表单与管理员面板。
- `clients/web/styles.css`：重做封面、CSS 轮盘主视觉、大厅目录、房间卡片、模态框和响应式布局；保留房间/棋盘的紧凑结构。
- `clients/web/app.js`：增加封面/大厅切换、模态开关、房间卡片唤起加入对话框和单人模拟自动开局流程。
- 项目文档：同步当前 Web 信息架构与本地试用流程。
