## 用户目标

暂缓服务器公网支线，优先实现可在本地测试的早期 Web 版本：构建 Core、本地 Host、简单随机机器人和浏览器交互，依据正式规则裁剪适合 MVP 的规则流程，并记录可持续演进的基础抽象。

## 范围与假设

- 一名浏览器玩家与 2～5 名本地随机 Bot 完成一局。
- 使用本机内存单局，不接入房间、账号、WebSocket、数据库或持久化。
- 客户端为零构建原生 Web 页面，降低玩法验证阶段的工具复杂度。
- 公网服务器部署模板及其他应用目录不在本次修改范围内。

## 关键决定

- 继续保持 `Browser → Backend → Host → Core → Domain` 单向依赖，不因本地运行而把规则复制到 JavaScript。
- Core 的地图、相遇、战斗和 Bot 分别使用显式随机流；相同种子和指令序列可重放。
- Bot 通过与人类相同的 `PlayerCommand` 进入 Core，只由 Host 负责调度。
- 将当前实际规则写成核心规则的 MVP 覆盖文档，明确试作概率和未实现范围。
- 本地服务只绑定 `127.0.0.1:8787`，页面静态资源编译进 Rust 可执行程序。

## 修改内容

- 完成 `roulette-domain` 的命令、状态、地形、事件、随机流和 Web 视图数据契约。
- 完成 `roulette-core` 的地图生成、移动、射击、肘击、水域、地雷、护盾、回合推进和胜负结算。
- 完成 `roulette-host` 的本地单局、revision 校验与随机 Bot 自动回合。
- 使用 Axum 和 Tokio 完成本地 HTTP API及嵌入式静态资源服务。
- 新增响应式本地 Web 页面、地图、玩家列表、操作面板、事件记录和键盘操作。
- 新增本地 MVP 规则、架构抽象、运行说明，并同步项目概览、模块说明、目录说明及公网支线状态。

## 验证

- `cargo fmt --all --check`：通过。
- `cargo test --workspace`：通过，Core 5 项、Host 3 项测试全部成功。
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`：通过，无警告。

## 遗留事项

- 当前 Bot 只做加权随机选择，不评估地图和生存收益。
- MVP JSON 契约尚未冻结为 `protocol/` 中的版本化公共协议。
- 地形生成不保证连通或平衡；规则概率需在试玩后调整。
- 公网房间、身份、幂等、重连、数据库和 WebSocket 支线暂缓。
