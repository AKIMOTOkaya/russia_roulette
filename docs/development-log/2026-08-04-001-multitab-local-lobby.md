# 2026-08-04：多标签页本地房间大厅

## 用户目标

- 用 Tab ID 区分浏览器标签页，把不同标签页视为不同真人玩家。
- 把单局首页改为多房间大厅，以五位、大小写无关的房间号创建和加入房间。
- 支持可选房间密码、房主转让/解散、最后真人退出自动解散及 Bot 席位管理。
- 启动时注入创始人临时密码，认证后由页面控制是否允许局域网访问。
- 按新房间模型重新设计 Web UI，同时保留紧凑对局操作区和自上而下的综合记录。

## 范围

- 扩展 `roulette-domain` 的 Tab、房间、成员与大厅视图契约。
- 将 `roulette-host` 从单局容器改为多房间内存大厅。
- 重做本地 Axum API、创始人设置与来源地址访问门。
- 重做原生 Web 大厅、房间、成员和对局界面。
- 同步本地 MVP 规则、架构、开发说明和项目模块说明。
- 不加入数据库、账号、WebSocket、公网安全机制或服务器部署修改。

## 关键决定

1. Tab ID 存在 `sessionStorage`：刷新和同页导航沿用；复制标签页造成存储副本时，通过同源 `BroadcastChannel` 冲突探测让新页面换用新 UUID。它是本地关联标识，不是认证令牌。
2. 房间码固定五位，生成字符排除易混淆字符，查找时统一大写；房间密码本身区分大小写。
3. 真人和 Bot 使用同一个成员/席位模型及相同 Core 指令入口。等待阶段由房主增删 Bot，总人数为 3～6 时可开局。
4. 对局中真人退出时把对应席位变为 Bot 托管；最后真人离开仍直接解散，避免留下纯 Bot 房间。
5. 页面轮询和心跳用于本地多标签页同步，15 秒无活动视为离开。公网版仍需正式重连语义。
6. 后端监听 `0.0.0.0`，局域网默认由中间件拒绝；只有先在回环来源验证创始人临时密码的 Tab 能开启开关。这只是本地软门。
7. 对局记录继续按 sequence 单列从上向下显示，真人和机器人的命令都标记为“行动”。

## 修改内容

- `roulette-domain`：新增 `TabId`、`RoomId`、`RoomMemberId`、房间阶段、成员、摘要、大厅与房间视图。
- `roulette-host`：新增 `LocalLobby`、房间创建/加入、密码校验、房主管理、Bot 管理、活动清理、席位托管及多真人行动映射；新增 6 项房间测试。
- `roulette-backend`：新增大厅/房间 REST 路由、心跳、创始人认证、局域网开关、启动密码注入和连接来源检查。
- `clients/web`：实现大厅首页、创建/加入表单、房间目录、创始人面板、统一成员列表、房主操作、多人棋盘和综合记录；使用轮询同步多个标签页。
- 文档：更新根说明、本地规则、架构、运行流程、模块划分、项目进度与客户端说明。

## 验证结果

- `node --check clients/web/app.js`：通过。
- `cargo fmt --all --check`：通过。
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`：通过。
- `cargo test --workspace`：通过，共 12 项单元测试和全部文档测试。
- 本机 API 冒烟：错误密码返回 403；小写房间号可正确加入；加入后密码可见；Bot 添加、房主转让、三人开局、真人 revision 行动和创始人 LAN 开关均通过。
- 浏览器冒烟：两个标签页获得不同 Tab ID 并进入同一房间；成员同步、Bot 补位、开局与操作区正常；记录 `#1` 至 `#4` 的屏幕位置按序向下递增。

## 遗留事项

- 房间结束后不能原地重开，也没有准备状态和观战模式。
- 轮询和 15 秒超时只适合本地试作；公网版需 WebSocket、正式会话、幂等和断线重连。
- 房间密码明文存储和公开显示是本地版本的明确取舍，不能沿用到公网。
- 需要继续补充 HTTP 层自动化测试、退出托管集成测试和移动端视觉回归。
